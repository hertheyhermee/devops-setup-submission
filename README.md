# Local DevOps Workstation

## Host and package manager

This setup uses Homebrew on macOS (Apple silicon). The host checked for this
submission has 16 GiB of RAM and approximately 48 GiB available on its data
volume, exceeding the project minimums of 4 GiB RAM and 10 GiB free disk space.

The relevant Homebrew packages are:

```sh
brew install git kubectl helm minikube awscli azure-cli node jq terraform ansible
brew install --cask visual-studio-code docker
```

Docker Desktop supplies the Docker Engine and Docker Compose plugin. Open Docker
Desktop and wait for its engine to start before using Docker or Minikube. Adjust
Docker Desktop's CPU and memory allocation if your workloads need it; leave
resources for macOS and other running applications.

Git is available for GitHub or GitLab repositories. AI coding assistants
and local LLMs are optional and are not required for the version checks.

## Start and verify the local cluster

```sh
minikube start --driver=docker
kubectl get nodes
```

The expected node status is `Ready`. The screenshot in `screenshots/` shows a
Minikube node in that state. The verification report is generated by:

```sh
./verify-tools.sh > verification/tooling-verification-report.txt 2>&1
```

The script exits nonzero if a required command, host resource threshold, or
cluster check fails. 

## Shell configuration

`environment/.zshrc` is a copy of the workstation's relevant zsh configuration.
It contains Herd-managed PHP/NVM paths and adds `~/.local/bin` to `PATH`; it
does not contain DevOps tool installation commands because Homebrew manages
those tools. Review machine-specific paths before copying it to another host.
The verification script is executable; run `ls -l verify-tools.sh` to inspect
its file permissions.

## Troubleshooting

- **Docker commands cannot connect:** launch Docker Desktop, wait until its
  engine reports running, then retry `docker info` and `docker compose version`.
- **Minikube does not start:** confirm Docker is running and has enough CPU and
  memory, then inspect `minikube status` and `minikube logs`.
- **kubectl targets another cluster:** run `kubectl config current-context`;
  use `kubectl config use-context minikube` to select the local cluster.
- **A command is not found after Homebrew installation:** open a new terminal
  and confirm `/opt/homebrew/bin` is on `PATH` on Apple silicon (`brew shellenv`).
- **Cloud CLI commands require authentication:** authenticate separately with
  `aws configure` or `az login` when needed. The version checks do not require
  cloud credentials.
